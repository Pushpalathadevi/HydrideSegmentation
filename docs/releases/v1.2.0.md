# MicroSeg v1.2.0 Release Notes

Release date: 2026-09-20

MicroSeg 1.2.0 lets the browser application rotate a micrograph into the tube's frame before
segmenting it, and shows the chosen image immediately instead of only once a run finishes. No
model weight, segmentation threshold or morphological footprint changes.

## Changes

### Rotating a micrograph into the circumferential/radial frame

Fn measures each hydride's angle against the image axes: the horizontal axis is taken as the
tube's circumferential direction and the vertical axis as its radial direction. Nothing in a
micrograph records how the tube was oriented, so that assumption could not be checked, and an
image captured in another frame returned an Fn measured against the wrong axes. Users reported
exactly this.

A new **Straighten and rotate** editor sits under the chosen image on the workspace page. It is
optional and collapsed by default, and it offers:

- 90-degree turns in either direction, and a fine-angle slider covering the quarter turn between
  them, with a total-rotation readout and a reset;
- a live preview over circumferential and radial guide lines, showing exactly the image that will
  be segmented;
- a degree badge on the collapsed header, so an applied rotation is visible without opening the
  editor.

On the server the rotation is applied to the decoded image before anything else, including the
downscaling limit. Therefore every view, measurement, mask and download describes the rotated
image:

- quarter turns are applied as an array transpose and are exactly lossless;
- any other angle is resampled once and then cropped to the largest upright rectangle that lies
  wholly inside the turned image. Cropping rather than padding is deliberate: padded corners
  would be invented pixels, and segmentation would measure them as part of the micrograph,
  biasing the area fraction and Fn;
- the run manifest `image` block adds `rotation_deg`, `rotation_applied`, `uploaded_width` and
  `uploaded_height`, while `width` and `height` still record the segmented size;
- the detailed PDF report prints the applied angle, so a result stays reproducible.

Requests carry the angle as the `rotation_deg` form field on both `POST /api/jobs` and
`POST /api/segment`. Omitting it means no rotation, so existing integrations are unaffected and
results for an image submitted without a rotation are identical to 1.1.1.

The scale of the correction is worth stating plainly. On the packaged
`reorienated_hydrides.png` with the conventional method, length-weighted Fn reads 0.026 upright
and 0.983 after a quarter turn. A micrograph mounted 90 degrees away from the assumed frame was
therefore reporting close to one minus the intended value.

### The chosen image appears immediately

Previously the preview slot was filled only after the browser had decoded the file, and TIFF —
the format most micrographs arrive in — never decoded at all, so those selections fell straight
through to "Preview is unavailable". Now the slot is revealed as soon as a file is chosen, and a
failed decode is retried once against the server:

- library and example images fall back to the thumbnail the server already caches;
- uploads are posted to a new `POST /api/preview`, which renders a JPEG thumbnail in memory and
  discards it. Nothing is written to disk, and no segmentation is run.

### Documentation

The help page gains an **Image orientation and rotation** section documenting the axes
assumption, what the rotation does to the pixels, and when to leave it at zero. The Fn help box
on the workspace page points at the editor.

## Upgrade and rollback

No persistent data, configuration schema or dependency changes. Restart the web service after
upgrading. Roll back by redeploying `v1.1.1`; nothing needs to be restored, because a rotation is
supplied per request and never stored.

## Verification

The complete suite passes locally with 386 tests and one intentional skip, and the release phase
gate reports `pass`. Thirty-three of those tests are new, covering angle normalization, lossless
quarter turns, the inscribed-rectangle crop, rotation ahead of downscaling, the preview endpoint,
and the browser assets.
