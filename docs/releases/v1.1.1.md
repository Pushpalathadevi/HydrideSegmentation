# MicroSeg v1.1.1 Release Notes

Release date: 2026-09-16

MicroSeg 1.1.1 makes web segmentation results match the uploaded image size and raises the
web upload limit. No model weight, segmentation threshold or morphological footprint changes.

## Changes

### Web results at the original image size

Images whose long side exceeds `limits.max_long_side_px` (default 2048 px) are still segmented
on a downscaled copy so jobs stay fast. Previously the mask, overlay and measurements were
returned at that reduced size. Now:

- the mask is enlarged back to the uploaded width and height with nearest-neighbour
  interpolation, so it keeps exactly the label values the model produced;
- the input, overlay and optional Fn classification views are drawn on the full-resolution
  upload;
- every measurement (area fraction, feature areas and lengths, Fn, minimum feature size) is
  computed on the restored mask and therefore refers to original-image pixels;
- the run manifest `image` block adds `output_width`, `output_height` and
  `mask_restored_to_original`, while `width` and `height` still record the segmented size;
- the result header reads "segmented at W x H px for speed, mask restored to original size".

Mask boundaries carry the detail of the downscaled image. For full-resolution segmentation set
`limits.max_long_side_px: 0`, at the cost of longer jobs.

Because measurements are now in original pixels, numbers for downscaled images differ from 1.1.0
results for the same file (for example, pixel areas scale by roughly 1/scale²; `min_feature_pixels`
now applies at the original resolution). Images within the limit produce identical results.

### Upload limit

`limits.max_upload_mb` now defaults to 10 MB (was 5 MB). Deployments that set it explicitly keep
their value.

### Maintenance

- `pypdf` is declared for test installations; `pyproject.toml` is the dependency authority and
  source distributions include the requirements profiles.
- Conventional segmentation uses the supported scikit-image morphology names in place of
  aliases scheduled for removal; regression snapshots confirm unchanged output.
- Version metadata reads 1.1.1 everywhere (the `v1.0.1` and `v1.1.0` tags were cut before the
  version files were updated).

## Upgrade and rollback

No persistent data, configuration schema or dependency changes. Restart the web service after
upgrading. Roll back by redeploying `v1.1.0`.

## Verification

The complete suite passes locally with 353 tests and one intentional skip, including new tests
for mask restoration (dimensions, exact label values, unchanged small images).
