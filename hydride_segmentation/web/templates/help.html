How to use this tool

This page explains what the tool does, which method to pick, and how to read the result. Everything runs on this server inside your intranet. Images you submit are held in memory for the duration of one request and are never written to disk or sent anywhere.

Quick start

  1. Open the Workspace.
  2. Drop your own micrograph onto the upload area, or select Browse the server library to pick one of the micrographs stored on this server. If this deployment has no library, two built-in examples are offered instead.
  3. Leave the method on its default and select Run segmentation.
  4. Look at the Overlay tab first: detected hydrides are tinted over your original image.
  5. If the overlay looks wrong, switch method or adjust the conventional settings one at a time.
  6. Read the Fn panel at the top of the results for the radial hydride fraction.

New here? Run one of the server's images once before using your own data. It shows you what a correct result looks like on this deployment, which makes it much easier to judge your own.

Choosing a method

Trained model

A neural network trained on labelled hydride micrographs. It generally handles varying contrast and illumination far better than thresholding, and needs no tuning. Use it first whenever it is offered. If the selector shows a trained model as unavailable, the server has no checkpoint file installed for it; ask whoever maintains this deployment to install one.

Conventional

A classical image-processing pipeline: contrast equalisation, adaptive thresholding, and morphological clean-up. It is fast, completely deterministic, and every step is inspectable, which makes it useful as a sanity check and for images unlike the training data. The cost is that you normally have to tune it for each new imaging condition.

A practical habit is to run both on the same image. Where they agree, you can be confident. Where they disagree, look closely at the original.

How the processing works

Both methods answer the same question — which pixels are hydride — and both hand back a binary mask. Everything after that point is identical, so the choice of method affects only the mask, never how the numbers are derived from it.

Every request follows these stages

  1. Validate

    extension → decoded format → frame count → pixel count

    The declared extension must match the format the decoder actually finds, so a renamed non-image is rejected. Multi-frame files are refused, and the decoded image may hold at most {{ "{:,}".format(config.max_image_pixels) }} pixels.

  2. Prepare

    decode → greyscale array{% if config.max_long_side_px %} → downscale if long side > {{ config.max_long_side_px }} px{% endif %}

    Colour images are converted internally.{% if config.max_long_side_px %} Downscaling is reported with the result, and every pixel measurement then refers to the downscaled image.{% endif %} The array stays in memory and is never written to disk.

  3. Segment

    image → binary mask M

    Either the conventional pipeline or a trained network, detailed below. This is the only stage where the two methods differ.

  4. Quantify

    label → per-feature orientation and length → Fn and distributions

    Connected components are measured individually; see Formulae for each definition.

  5. Report

    PNG views + metrics + settings → JSON

    The downloaded JSON records the settings that produced the numbers, so a result can be reproduced later.

The two pipelines fail in different ways, which is what makes running both worthwhile. The conventional method mistakes any dark elongated feature — a scratch, a polishing artefact — for a hydride. The trained model rejects those, but can miss hydrides that look unlike anything in its training set. Agreement between them is real evidence; a disagreement tells you which image to look at closely.

Radial hydride fraction (Fn)

Fn is the share of hydrides oriented radially rather than circumferentially. It is the number most often wanted from a hydride micrograph, because radial hydrides are the ones that matter for through-wall crack paths.

How it is measured here

  1. Each connected feature in the segmentation mask is isolated and skeletonised.
  2. Its dominant direction is measured as an angle from the horizontal, folded into 0–90°.
  3. Features at or above the angle threshold count as radial.
  4. Two fractions are reported.

The two Fn numbers

Fnlength = Σ radial skeleton length ÷ Σ measured skeleton length; Fncount = radial feature count ÷ measured feature count.

Length-weighted Fn
Total length of radial hydrides divided by total length of all measured hydrides. This is usually the one to report. It reflects that one long radial hydride is more significant than several short ones, and it is far less sensitive to how many tiny features the segmentation happened to detect.
Count-based Fn
Number of radial hydrides divided by the number of measured hydrides. Simple to explain, but easily distorted: if the segmentation picks up hundreds of single-pixel specks, they all count equally against one large hydride. Raise the minimum feature size if this number looks wrong.

Checking the number is trustworthy

Tick Show which hydrides were counted before running. Two extra views appear:

  • Fn counted outlines each counted feature in green and each uncounted one in red, labelling the largest counted features with their angle and length. Use it to confirm the classification matches what you see by eye.
  • Fn threshold plots the orientation histogram with the threshold drawn on it. If a large peak sits right at the threshold line, Fn is sensitive to exactly where you set it, and you should say so when reporting the value.

Always report the angle threshold and the minimum feature size alongside Fn. The same image can legitimately give different Fn values under different conventions, so the number is only comparable when those settings are stated. Both are recorded in the downloadable JSON.

Fn depends on the segmentation being right in the first place. Check the Overlay tab before trusting any number, and prefer the trained model where it is available.

Formulae

Every number in the measurements table and the downloaded JSON is defined below. The monospaced name after each definition is the key it appears under in the JSON, so a value in a report can always be traced back to its definition.

1. Extracting features from the mask

All measurements begin from the same decomposition of the mask into individual hydrides.

  1. Label connected components

    M → { R1, R2, …, RN }

    Pixels are grouped using 8-connectivity, so features touching only at a corner are treated as one. Components smaller than the minimum feature size are dropped before any statistic is computed excluded_small_features.

  2. Reduce each feature to a centreline

    \(R_i\) → fill holes → dilate(disk 1) → skeletonise

    The skeleton is a one-pixel-wide centreline. Filling and a single dilation first keep a ragged edge from breaking the skeleton into disconnected stubs.

  3. Find the dominant direction

    \(\Sigma = \operatorname{cov}(\text{skeleton coordinates})\);   \(\mathbf{v}_i\) = eigenvector of \(\Sigma\) with the largest eigenvalue

    This is principal component analysis on the centreline points: the leading eigenvector is the direction along which the feature is most extended.

Feature orientation \[ \theta_i^{\text{raw}} = \operatorname{atan2}(v_y,\, v_x) \bmod 180^\circ, \qquad \theta_i = \begin{cases} \theta_i^{\text{raw}} & \text{if } \theta_i^{\text{raw}} \le 90^\circ \\[2pt] 180^\circ - \theta_i^{\text{raw}} & \text{otherwise} \end{cases} \]
\(\theta_i\)
angle of feature i from the horizontal, folded into 0–90°. A line has no head or tail, so a direction and its reverse are the same orientation; folding removes that ambiguity. 0° is horizontal (circumferential), 90° vertical (radial).
Feature length \[ L_i = \max_{p \in R_i} (p \cdot \mathbf{v}_i) - \min_{p \in R_i} (p \cdot \mathbf{v}_i) + 1 \]
\(L_i\)
extent of the feature along its own dominant direction, in pixels. Every pixel of the feature is projected onto the direction vector and the span of those projections is taken; the +1 counts the end pixel itself, so a single-pixel feature has length 1.

2. Radial hydride fraction

Count-based Fn \[ \mathrm{Fn}_{\text{count}} = \frac{\bigl|\,\{\, i : \theta_i \ge \theta_c \,\}\,\bigr|}{N} \]
\(\theta_c\)
angle threshold, 45° by default fn_angle_threshold_deg
\(N\)
number of measured features, after the minimum size filter fn_count_denominator

fn_count

Length-weighted Fn \[ \mathrm{Fn}_{\text{length}} = \frac{\sum_{i \,:\, \theta_i \ge \theta_c} L_i}{\sum_i L_i} \]
numerator
total length of radial hydrides fn_length_numerator_px
denominator
total length of all measured hydrides fn_length_denominator_px

fn_length_weighted — normally the value to report; see the Fn section for why.

3. Coverage

Area fraction \[ \varphi = \frac{N_{\text{hydride}}}{N_{\text{total}}} \]
\(N_{\text{hydride}}\)
count of mask pixels classified as hydride hydride_total_area_pixels
\(N_{\text{total}}\)
total pixels in the processed image

hydride_area_fraction, and ×100 as hydride_area_fraction_percent. Note this counts every mask pixel, including features excluded from the per-feature statistics as too small.

Feature density \[ \rho = \frac{N}{N_{\text{total}} / 10^{6}} \]
\(\rho\)
measured features per megapixel hydride_density_per_megapixel

4. Feature size

Equivalent circular diameter \[ d_i = 2\sqrt{\frac{A_i}{\pi}} \]
\(A_i\)
area of feature \(i\) in pixels
\(d_i\)
diameter of the circle with the same area. It is a single-number size for an irregular shape, and for a long thin hydride it is much smaller than the length Li — the two describe different things.

equivalent_diameter_*_px

5. Orientation dispersion

Alignment index \[ A = \left| \frac{1}{N} \sum_{i=1}^{N} e^{\,j\,2\theta_i} \right| \]
\(A\)
circular resultant length, between 0 and 1. The angle is doubled before averaging because orientations repeat every 180°; without that, hydrides just above and just below horizontal would cancel instead of reinforcing. A = 1 means every hydride points the same way; A near 0 means orientations are spread evenly.

orientation_alignment_index

Orientation entropy \[ H = -\sum_k p_k \log_2 p_k, \qquad p_k = \frac{c_k}{\sum_k c_k} \]
\(c_k\)
count in bin \(k\) of the orientation histogram
\(H\)
spread of the orientation distribution in bits. \(H = 0\) means every hydride falls in one bin; the maximum, \(\log_2 B\) for \(B\) bins, means they are spread evenly across all of them. Because it depends on the bin count, compare \(H\) only between runs using the same number of orientation bins.

orientation_entropy_bits

6. Summary statistics

Orientation and size are each summarised with the mean, median, standard deviation, 10th and 90th percentiles, minimum, and maximum, taken over the measured features.

Standard deviation \[ \sigma = \sqrt{\frac{1}{N} \sum_{i=1}^{N} \left(x_i - \bar{x}\right)^2} \]
\(\sigma\)
population standard deviation, dividing by \(N\) rather than \(N-1\). The features are the whole population being described, not a sample drawn from a larger one.

orientation_std_deg, size_std_pixels

Orientation statistics are ordinary linear statistics over angles folded into 0–90°, not circular statistics. That is the right choice here because the folded range has genuine endpoints — circumferential at 0° and radial at 90° — but it means the mean orientation is not meaningful for a strongly bimodal specimen with hydrides at both extremes. Use the alignment index and the histogram in that case; the alignment index is computed circularly.

7. Scale calibration

Pixels to physical units \[ A_i^{\,\mu\mathrm{m}^2} = A_i \, s^2, \qquad d_i^{\,\mu\mathrm{m}} = d_i \, s \]
\(s\)
scale in microns per pixel

This browser tool does not know your image scale, so s is unset and every measurement it reports is in pixels. Fn is unaffected, because it is a ratio of lengths and the scale cancels. Use the desktop application when you need calibrated areas or diameters.

Reading the results

  • Overlay — detected regions drawn over your original image. The fastest way to judge quality.
  • Input — the image exactly as the server processed it, after any downscaling.
  • Mask — the binary segmentation on its own. This is what you download for further analysis.
  • Orientation — detected features coloured by their measured angle.
  • Size and Angle — distributions across all detected features.
  • Fn counted and Fn threshold — shown when you tick the Fn option; see the Fn section.

The Fn panel sits above everything else because it is normally the headline result. Below it, measurements are grouped into Fn, coverage, orientation, and feature size; open a group to see its numbers, and use Download JSON to save all of them together with the settings that produced them.

Area fraction is the proportion of image pixels classified as hydride, so it depends on the field of view you imaged. Compare it only across images taken at comparable magnification and framing.

Measurements are reported in pixels. This browser tool does not know your image scale, so it cannot convert to microns. Use the desktop application when you need calibrated measurements.

Troubleshooting

The trained model is greyed out
No checkpoint file is installed on this server for it. The conventional method still works. Whoever maintains the deployment can install a checkpoint and it will appear here.
The result is empty or nearly empty
With the conventional method, lower the adaptive threshold offset or the minimum feature area. If a trained model returns nothing, the image is probably very different from what it was trained on; try the conventional method instead.
Everything is detected, including the background
Raise the adaptive threshold offset, or lower the CLAHE clip limit so noise is not amplified.
Count-based Fn looks far too high or too low
Usually noise. Raise Minimum feature size for statistics so single-pixel specks stop counting as hydrides, and compare against the length-weighted value, which is much less affected. Tick Show which hydrides were counted to see exactly what was included.
Fn changes a lot when I nudge the threshold
That means many hydrides sit close to the threshold angle. Open the Fn threshold view to see the histogram with the threshold marked, and report the threshold you used alongside the value.
The server says it is busy
Several colleagues are running jobs at once. The request was not lost; wait a moment and run again.
The first run of the day is slow
The server loads models into memory at startup, so this should be rare. If it happens, the server was probably restarted moments earlier. The status indicator in the header turns green once models are loaded.
